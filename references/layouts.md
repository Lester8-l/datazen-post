# 版型菜單（7 款 + 1 個懶人包版型）

一個 `data-type` 對應一個版型。每張卡的 HTML 骨架照抄，只換文字。

## 字數預算（42px 正文 ≈ 手機 15px）

| 位置 | 每行上限 |
|---|---|
| 封面主標 / 宣言 | 10 字 |
| 次標題、對照欄 | 16 字 / 8 字 |
| 正文、表格、行動列 | 22 字 |
| 說明句 | 26 字 |

超了就換行或減字，不要降字級——降字級等於退回手機看不清的老問題。

## 選版規則

- **開場**：`cover`。**收尾**：`end`。
- 中間 4–6 張從 `statement` / `number` / `table` / `compare` / `rules` 挑，**同款不連續**。
- 一張卡只講一件事。兩個重點就拆兩張。
- **每三張要有一張「有數據」的**（`number` 或 `table`），否則整條 feed 會變成語錄。
- 節奏：文字重的（`table`、`pack`）之間插留白多的（`statement`、`cover`）。

---

## C1 · `cover` 封面

```
頂欄 → 《小標》→ 手寫主張（126px）→ 主標（68px）→ 括號標註 → 刻度 → metadata
```

- 手寫那句是**情緒鉤子**，主標是**內容承諾**，兩者不要講同一件事。
- 括號標註把主標拆成可兌現的清單：`3　危疾 · 醫療 · 退休`。
- metadata 用三個真實數字：`3 POLICIES · 47 CLAUSES · 11 DUPLICATED`。

**適合**：每篇第一張，永遠。
**不要**：在封面放表格。

---

## C2 · `statement` 宣言

```
頂欄 → kicker → 大標（78px，可含 em 強調）→ 副句（32px 楷體）→ 手寫批註
```

- 一句核心主張，不超過兩行。第二行就是轉折。
- 手寫批註是「補一刀」，不是重複大標。

**適合**：立場、價值觀、反潮流觀察。
**不要**：連續兩張宣言。

---

## C3 · `number` 數字

```
頂欄 → kicker（OVERLAP RATIO）→ 大數字（262px）→ 一句說明 → 疊加條 → 刻度 → metadata
```

- 數字必須有出處（寫在 metadata 的 `SOURCE`）。
- 疊加條的紅段＝問題所在；兩段加起來要是 100%。
- 說明句用「你嘅⋯⋯有三成四係重複嘅」的口語，不要寫成報告語氣。

**適合**：比例、增幅、差距。**這是最能建立「數據人」人設的一版。**

---

## C4 · `table` 明細

```
頂欄 → kicker → 領句（42px）→ 表頭 → 3–4 行 → 刻度 → metadata
```

- **一定要有領句**（`.tbl-lead`）。表格本身撐不起一張卡，上半空了就會變成「小字浮在大空間」。
  領句寫表格的結論，不是描述：`三份保單，兩份重複。`

- 最多 4 行（含合計）。第 5 行開始客戶不會讀。
- 單元格 ≤ 8 字（欄寬約 250–380px，42px 字級）。
- 欄位：`c4` 保單／保額／用途／重複；`c3` 項目／數值／備註；`c2` 項目／數值。
- 問題行用 `<i class="on">` 紅點，只在「重複」欄用。
- 最後一行放合計或結論（`合計有效 66%`），讓表格自己收尾。

**適合**：保單盤點、費用拆解、選項對比。
**不要**：把表格當成內容本身——它要支撐一句結論。

---

## C5 · `rules` 清單／行動

```
頂欄 → 手寫主張（99px，置中）→ 副句 → 三行動作列 → 刻度 → metadata
```

- 三條，每條 ≤ 14 字，右邊掛一個英文動詞：`KEEP` / `MERGE` / `CUT`。
- 動詞是「顧問交付」的語言，不是「關單」的語言。
- 第三條最好帶一個可計算的結果（`保費落返 34%`）。

**適合**：方法論收束、框架、checklist。

---

## C6 · `compare` 對照

```
頂欄 → kicker → 兩欄（左：你以為／右：實際）→ 垂直細線 → 結論行 → 刻度 → metadata
```

- 左欄用主文字色，右欄的標籤用淺赭（`after`），形成「被糾正」的視覺。
- 每欄：標籤（mono）→ 主張（54px 楷體）→ 一句解釋（34px）。
- **`.cmp-foot` 結論行**：兩欄下面一句 42px 楷體，前掛 mono 小標籤「結論」。對照卡主體覆蓋率本來只有約 39%，冇落點會令兩欄浮喺霧入面；一句結論令佢有起承轉合。
- 對照的是**認知**，不是產品。左邊寫客戶的誤解，右邊寫實際機制。

**適合**：破除迷思、認知落差。
**不要**：拿同業產品做對照（合規風險）。

---

## C7 · `end` 收尾

```
頂欄 → 手寫主張（104px）→ 副句（46px）→ CTA 細框 → 名額說明 → 刻度 → metadata
```

- CTA 是**一個細框**，不是按鈕。`每週 3 個深度審視名額`。
- 下面補一句降低壓力的話：`DM「審視」· 我會先問你三個問題`。
- 邊界感就是這樣做出來的：不催、不逼、給名額。

**適合**：每篇最後一張。
**不要**：放 WhatsApp 號碼大字、放價格、放「立即報名」。

---

## P1 · `pack` 客戶懶人包（單張）

```
頂欄（懶人包 · 主題）→ kicker（3 分鐘讀完）→ 標題（48px）→ 副題
→ 事實三條（階梯錯位）→ 同你有咩關係 → 一句講完（手寫）→ 刻度 → .src（來源＋免責）
```

- 事實**只有三條**，每條：編號 + 短標（30px）+ 一句解釋（25px）。
- 三條用 CSS 階梯錯位（0 / 44 / 88px），破「等寬網格」的 AI 味。
- `.src` 是**執照**：`資料來源：〈機構全名〉｜YYYY.MM`，加免責句。沒有就不准交付。
- 客戶姓名、保單號一律不可出現——圖會被轉發給家人。

**適合**：新聞解讀、政策、MPF、醫療、稅務。
**不要**：超過三條事實；客戶不會讀第四條。

---

## 輪播三頁結構（懶人包 3 張版）

`cover`（深霧封面，大字）+ `pack` 或 `table`（重點）+ `end`（結論，軟性或引導）。

三頁都要有 `.src`——封面也會被單獨截圖轉發。
