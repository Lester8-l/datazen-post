# 內容框架：資訊 → 懶人包

這份文件是 skill 的大腦。排版只佔 10% 工夫，剩下 90% 是「點樣把一件事壓縮成客戶肯睇完嘅三句話」。

---

## 一、核心假設

客戶**唔會讀原文**。不是懶，是沒時間——一份研究報告 40 頁、一條新聞 1200 字，
他要的是「我需要知咩」。

所以你做的不是摘要（summary），是**翻譯（translation）**：

| | 摘要 | 翻譯（懶人包） |
|---|---|---|
| 動作 | 把原文縮短 | 把原文換成「對佢嘅意義」 |
| 主語 | 報道／機構 | 你 |
| 客戶讀完的反應 | 「哦，知道咗」 | 「咦，咁我點算？」 |

**觸發對話，才是懶人包的目的。** 純摘要發出去，客戶只會回一個 👍，然後沒有然後。

---

## 二、三層翻譯法（本 skill 的骨架）

每一份懶人包都必須有齊三層，順序不能調：

| 層 | 名稱 | 寫法 | 篇幅 | 範例 |
|---|---|---|---|---|
| **L1** | 發生咩事 | 純事實，可核實，不加工 | 3 條，每條 ≤ 30 字 | 醫療成本升幅一般高於整體通脹 |
| **L2** | 點解關你事 | 把 L1 接去客戶的人生場景 | 1 段，≤ 50 字 | 醫療開支唔係一次過嘅事，係一條越拉越長嘅尾巴 |
| **L3** | 你可以點做 | 一句可記住、可執行的話 | 1 句，≤ 20 字 | 準備得早，選擇權喺你手 |

**L2 是這份懶人包值錢的地方，也是你同 AI 摘要的分別。**
L1 任何人都寫得出，L2 需要你懂客戶的人生。如果 L2 寫不出來，代表這件事跟你的客戶無關——不要發。

**L1 嚴禁加工**：原文寫「上升 12%」，就唔可以寫「大幅上升」；
原文寫「研究發現相關性」，就唔可以寫成「導致」。改一個動詞就係失實。

---

## 三、標題公式（hook）

標題決定客戶會唔會睇第二行。四種寫法，揀一種：

| 公式 | 結構 | 範例 |
|---|---|---|
| **直接問句** | 用「你」開頭問一個他真的答不出的問題 | 你嘅預算跟得上嗎？ |
| **數字對比** | 同一件事，兩個數字並排 | 同樣一筆錢，十年後買少三成服務 |
| **反常識** | 講一個跟他直覺相反的結論 | 最貴嘅唔係手術費，係之後嗰十年 |
| **場景具體化** | 一句畫出一個畫面 | 45 歲確診，收入斷咗，但供樓唔會停 |

**不要用**：
- ❌ 照抄新聞標題（「衞生署今日公布最新數據」）—— 冇人關心機構動作，只關心自己
- ❌ 抽象名詞開頭（「醫療通脹趨勢分析」）—— 似論文，唔似人講嘅話
- ❌ 誇張恐嚇（「唔買保險你會後悔一生」）—— 客戶即刻封鎖你

---

## 四、來源規範（最重要，硬性）

來源不是裝飾，是這類內容的**執照**。冇來源 = 你的個人意見 = 客戶轉發出去出事你負責。

### 必填格式

```
資料來源：<機構／媒體名稱>｜<日期>
```

- 機構／媒體名稱**要寫得出全名**。「某大報」「有報道指」等於冇寫。
- 日期：月度資訊用 `2026.10`；新聞用 `2026.10.08`。
- 一篇懶人包**只用一個主來源**。真要多個，分開列，不要混在一行。

### 一律不可用的來源

| 字樣 | 為什麼不可用 |
|---|---|
| 據悉／據了解／消息指 | 等於承認冇查證 |
| 網上流傳／聽講／朋友講 | 不可核實 |
| 專家指出／有醫生表示（冇名） | 匿名權威，違規風險 |
| 「研究顯示」（冇機構冇年份） | 最常見的偷懶寫法，`check-source.py` 會抓 |

### 三條鐵律

1. **不得改寫數字**。原文寫幾多就寫幾多，可以簡化單位（1,200,000 → 120 萬），不可以改變量級。
2. **連結唔印在圖上**。URL 印在 1080px 寬的卡上一定斷行、一定會被裁，而且冇人打得入。連結放 WhatsApp 配文。
3. **數字要有時間標籤**。「醫療通脹 8%」是冇意義的；「2026 年醫療通脹 8%」才有意義。

> 這三條由 `scripts/check-source.py` 機械檢查，缺來源或缺日期一律 exit 1，不准交付。

## 五、題材禁區

你的身份是持牌顧問，唔係記者。以下四類要特別小心：

| 禁區 | 問題 | 正確做法 |
|---|---|---|
| 醫療新知 → 寫成醫療建議 | 「呢隻藥有效」「你應該去驗」 | 只講「研究發現／機構建議」，並加「不構成醫療建議」 |
| 市場資訊 → 寫成投資建議 | 「而家係入市好時機」 | 只講已發生的事實，加「投資涉及風險」 |
| 政策消息 → 寫成已落實 | 「政府將加稅」 | 寫明階段：「建議／草案／諮詢中／已通過」 |
| 個案故事 → 冇授權就引用 | 用真實客戶案例 | 改寫成虛構但貼近真實的情境，不要可辨識任何人 |

另外一律不做：政治敏感題材、未經核實的醫療傳言、任何要求你預測市場走向的內容。

## 六、版型選擇決策

```
題目只有一個核心數字／一句話？
├─ 係 → 單張（L1 / L2）
└─ 否 → 有 3 個以上要點要展開？
         ├─ 係 → 輪播 3 頁（L3）
         └─ 否 → 單張

客戶關係係？
├─ 已建立信任，可以提服務 → 結尾用「行動版」（L2 / L3-3b）
└─ 仲喺養關係階段 → 結尾用「軟性版」（L1 / L3-3a）
```

**不確定就用 L1 + 軟性。** 推銷味太重的懶人包，發第二次就冇人睇。

## 七、WhatsApp 配文（文字稿必附）

圖是主體，但**配文才是開場**。客戶先讀配文決定要唔要點開圖。

固定四段結構：

```
① 一句開場（唔好「分享一篇文章俾你」，太冇誠意）
② 三個 bullet：直接寫圖上三條 L1
③ 一條開放式問題（不要問「有冇興趣」，要問生活場景）
④ 來源連結
```

範例：

> 啱啱睇到一份關於醫療開支嘅資料，有幾個位幾值得留意。
>
> • 醫療成本升幅一般高於整體通脹
> • 公營輪候時間越拉越長，更多人轉用私營
> • 開支往往集中喺人生最後十年
>
> 你身邊有冇人係因為醫療開支而打亂咗原本嘅計劃？
>
> 原文：<連結>

**唔好問「有興趣了解多啲嗎？」** —— 這是推銷句式，客戶會啟動防禦。
問一個他願意分享的生活問題，對話才會開始。

## 八、常見錯誤

1. **L2 缺席**：只有事實，冇「同你有咩關係」。→ 變成一則普通新聞，客戶唔會記得你。
2. **塞太多**：想完整就寫 5 條 8 條。→ 一頁紙塞 3 條已經係上限，第 4 條開始客戶就掃。
3. **照抄原文語序**：原文係書面語嘅機構聲明，直接搬過來會硬。→ 要重寫成講得出口嘅話。
4. **來源寫喺配文冇寫喺圖**：圖會被單獨轉發。→ 每張卡**都要**有來源，包括封面。
5. **關鍵字濫用**：金色關鍵字變成滿版金色。→ 3–6 個就夠，只挑真正嘅重點。
6. **封面同內頁同性質**：三頁都係文字牆。→ 封面要大、內頁要疏、結尾要有留白。
7. **冇下一步**：睇完覺得「哦」，但唔知可以問你咩。→ 結尾一定要有一句可記住的話或明確行動。
8. **過期**：用咗兩年前嘅數據。→ 每次都要重新核對時效，數字會過時。
